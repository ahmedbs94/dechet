\chapter{Environnement de travail}
\label{chap:environnement_travail}

\section{Introduction}

Ce chapitre présente l'environnement de travail adopté pour la conception et la réalisation de la plateforme \textit{EcoRewind}. Il décrit l'architecture logicielle de l'application, les technologies employées pour le développement frontend et backend, les services de données utilisés ainsi que les outils mobilisés durant le cycle de développement.

\section{Architecture logicielle}
\label{sec:architecture_logicielle}

Afin d'assurer la modularité, la maintenabilité et l'évolutivité de la plateforme, \textit{EcoRewind} repose sur une architecture client--serveur. Cette architecture sépare l'interface utilisateur, la logique métier, la persistance des données et les services temps réel.

L'application cliente est développée avec Flutter. Elle est utilisée par les différents profils de la plateforme, notamment le citoyen, l'éducateur, le collecteur, le gestionnaire de point et l'administrateur. Elle permet de consulter les points de collecte, de participer aux activités de sensibilisation, de scanner les QR codes des bacs intelligents, de suivre les scores et d'accéder aux tableaux de bord adaptés aux rôles.

La logique métier est centralisée dans une API REST développée avec FastAPI. Cette API assure l'authentification, le contrôle des accès, la gestion des utilisateurs, des publications, des quiz, des points de collecte, des tournées et des notifications. Les données métier sont stockées dans PostgreSQL, tandis que Firebase est utilisé pour les données nécessitant une synchronisation en temps réel, telles que les scores, l'état des bacs intelligents et les notifications.

\subsection{Avantages de l'architecture retenue}

L'architecture retenue offre plusieurs avantages pour la plateforme :
\begin{itemize}
    \item \textbf{Séparation des responsabilités :} Flutter gère l'interface utilisateur, FastAPI centralise les règles métier et PostgreSQL assure la persistance des données transactionnelles.
    \item \textbf{Accès multiplateforme :} une même application Flutter peut être exécutée sur Android, iOS et le Web.
    \item \textbf{Évolutivité :} les fonctionnalités backend sont organisées en modules et routeurs spécialisés, ce qui simplifie l'ajout de nouveaux services.
    \item \textbf{Réactivité :} Firebase Realtime Database permet de diffuser rapidement les informations liées aux scores et à l'état des équipements connectés.
    \item \textbf{Sécurité :} l'accès aux ressources est contrôlé par des jetons JWT et par une gestion des droits selon les rôles des utilisateurs.
\end{itemize}

\subsection{Architecture technique}

La figure \ref{fig:architecture_technique_ecorewind} détaille les échanges entre les composants techniques. L'application Flutter communique avec le backend FastAPI par des requêtes HTTP sécurisées. Le backend applique les règles métier et utilise PostgreSQL pour les données persistantes. Il communique également avec Firebase pour synchroniser les données temps réel et envoyer les notifications.

Les données sensibles de Firebase ne sont pas modifiées directement par le client Flutter. Les écritures sont réalisées par le backend à l'aide du SDK Firebase Admin, ce qui renforce le contrôle et la sécurité des opérations. Les bacs intelligents et les QR codes participent au suivi des opérations de tri et de collecte.

\section{Outils et technologies}
\label{sec:outils_technologies}

Le choix des technologies a été guidé par la nécessité de fournir une application multiplateforme, réactive, sécurisée et adaptée à la gestion des données liées au tri des déchets.

\subsection{Développement Frontend et Backend}

\subsubsection{Flutter et Dart}

Flutter est le framework utilisé pour développer la partie frontend d'\textit{EcoRewind}, tandis que Dart est le langage de programmation associé. Cette technologie permet de créer une application multiplateforme à partir d'une base de code unique.

Le frontend fournit les interfaces permettant aux citoyens et aux autres acteurs de consulter les informations de la plateforme, localiser les points de collecte, scanner un bac, suivre les éco-points, participer aux quiz, publier des contenus et recevoir des notifications. Flutter facilite également la création d'interfaces réactives et cohérentes sur les différents supports.

\subsubsection{Python et FastAPI}

La partie backend est développée avec Python et FastAPI. FastAPI est un framework moderne permettant de concevoir une API REST performante et structurée. Il assure la communication entre l'application Flutter, la base de données PostgreSQL et les services Firebase.

Le backend d'\textit{EcoRewind} gère notamment l'authentification des utilisateurs, les rôles et permissions, les points de collecte, les bacs intelligents, les publications communautaires, les quiz, les groupes, les réunions, les statistiques et les notifications. FastAPI fournit également une documentation interactive de l'API, utile pour tester les différents services.

\subsection{Base de données : PostgreSQL, SQLAlchemy et Alembic}

PostgreSQL est le système de gestion de base de données relationnelle utilisé pour stocker les informations métier de la plateforme. Il contient notamment les comptes utilisateurs, les rôles, les points de collecte, les publications, les quiz, les interventions et les historiques nécessaires au suivi de l'application.

SQLAlchemy assure la communication entre les modèles Python et PostgreSQL. Alembic est utilisé pour gérer les migrations du schéma de données. Cette combinaison permet de faire évoluer la structure de la base de données de manière contrôlée. SQLite peut être utilisé localement comme solution de développement, mais PostgreSQL est retenu pour les environnements de production.

\subsection{Services Firebase}

Firebase complète l'architecture pour les besoins de synchronisation et de communication en temps réel. Les services principaux utilisés sont :
\begin{itemize}
    \item \textbf{Firebase Authentication :} authentification auprès de l'écosystème Firebase à partir de jetons générés par le backend ;
    \item \textbf{Firebase Realtime Database :} consultation en temps réel des scores, de l'état des bacs intelligents et de certaines statistiques ;
    \item \textbf{Firebase Cloud Messaging :} envoi de notifications push vers les appareils mobiles.
\end{itemize}

Cette intégration permet de mettre à jour rapidement les informations visibles par les utilisateurs, tout en maintenant le backend comme point de contrôle des écritures sensibles.

\subsection{Sécurité et authentification}

La sécurité des échanges repose sur des jetons JWT émis par le backend. Chaque utilisateur est authentifié avant l'accès aux ressources protégées. Le contrôle d'accès basé sur les rôles limite les actions disponibles selon le profil connecté. Les mots de passe sont stockés sous forme hachée et des mécanismes complémentaires, tels que les codes OTP et l'authentification multifacteur, peuvent renforcer la protection des comptes.

\subsection{Outils de développement et de collaboration}

Les outils suivants ont été utilisés pour réaliser, tester et documenter la plateforme :
\begin{itemize}
    \item \textbf{Visual Studio Code :} éditeur de code pour le développement Flutter, Dart, Python et les fichiers de configuration ;
    \item \textbf{Android Studio et les outils Flutter :} émulation, exécution et débogage de l'application mobile ;
    \item \textbf{Postman :} test des points d'entrée de l'API REST et validation des réponses ;
    \item \textbf{Git et GitHub :} gestion des versions, sauvegarde du code source et collaboration ;
    \item \textbf{Draw.io :} conception des diagrammes d'architecture et de modélisation ;
    \item \textbf{Firebase Console :} configuration et administration des services Firebase.
\end{itemize}

\section{Environnement de développement}
\label{sec:environnement_developpement}

L'environnement de développement réunit les outils nécessaires à la construction, à l'exécution et aux tests des différentes couches d'\textit{EcoRewind}. L'application Flutter peut être exécutée sur un émulateur Android, un appareil physique ou un navigateur Web. Le serveur FastAPI est lancé localement afin d'exposer les services REST, tandis que PostgreSQL est configuré au moyen des variables d'environnement du projet.

Le cycle de développement consiste à implémenter ou adapter une fonctionnalité côté Flutter et FastAPI, appliquer les migrations Alembic lorsque le schéma de données évolue, puis vérifier le fonctionnement de l'API à l'aide de la documentation interactive FastAPI ou de Postman. Les services Firebase sont ensuite utilisés pour valider les fonctionnalités de notification et de synchronisation en temps réel.

\section{Conclusion}

Ce chapitre a présenté l'environnement de travail de la plateforme \textit{EcoRewind}. L'architecture client--serveur retenue associe Flutter et Dart pour l'interface multiplateforme, Python et FastAPI pour les services métier, PostgreSQL pour la persistance des données et Firebase pour la synchronisation temps réel et les notifications.

Cette organisation permet de répondre aux besoins de la plateforme tout en préservant la modularité, la sécurité des accès et la capacité d'évolution. Les outils de développement et de test adoptés constituent une base cohérente pour la réalisation et la validation continue des fonctionnalités d'EcoRewind.
